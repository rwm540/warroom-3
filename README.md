## 🎯 معرفی کلی پروژه
پلتفرم **«اتاق جنگ»** یک سامانه تعاملی مدرن به سبک بازی‌های استراتژیک (مشابه Clash of Clans و داشبوردهای فرماندهی تاکتیکی) است که برای هدایت مأموریت‌های کتاب‌خوانی، چالش‌های گروهی، تولید محتوای چندرسانه‌ای و ارتقای مهارت‌های نوجوانان طراحی شده است. کاربران در قالب جوخه‌ها و تیم‌های عملیاتی عضو شده، مراحل داستانی را پشت سر گذاشته، کریستال و امتیاز تجربه (XP) کسب کرده و برای دستیابی به ۹ جایزه رویایی و فتح سکوی قهرمانی به رقابت می‌پردازند.

## ✨ ویژگی‌ها و قابلیت‌های شاخص

### ۱. سیستم احراز هویت و امنیت هوشمند
* **ورود بر پایه کد ملی (National ID):** ورود مستقیم با کد ملی ۱۰ رقمی معتبر و رمز عبور.
* **بازیابی رمز عبور با تأیید مدیر (Secure Reset):** کاربر با کد ملی و شماره تماس، «درخواست تغییر رمز» ثبت می‌کند؛ مدیر در پنل، شماره تماس را می‌بیند، تلفنی احراز هویت می‌کند و رمز جدید (هش‌شده با scrypt) را تعیین و اعلام می‌نماید. رمز جدید در دیتابیس هرگز به‌صورت متن ساده ذخیره نمی‌شود.
* **لایه‌های امنیتی سرور:** محدودسازی نرخ و ضدحمله DDoS، ضد SQL Injection، CSRF، CSP، قفل حساب پس از تلاش‌های ناموفق، نشست امن و گزارش رخدادهای امنیتی (Audit Log).
* **تفکیک خودکار نقش‌ها:** ورود به عنوان رزمنده/فرمانده جوخه، بازرس یا مدیر ارشد عملیات (Admin).

### ۲. آموزش تعاملی فرمانده (Onboarding Tutorial)
* راهنمای گام‌به‌گام و دیالوگی به سبک بازی‌های استراتژیک با حضور فرماندهان هوشمند پویش.
* معرفی بخش‌های نقشه، جوایز، ویترین آثار و جدول رده‌بندی به کاربر با قابلیت رد کردن (Skip) یا رفتن به مراحل بعد.

### ۳. جلوه‌های بصری نئونی و رادار ۳۶۰ درجه
* پس‌زمینه تاکتیکی دارک‌مود همراه با اسکنر راداری چرخان (`radar-sweep`) و شبکه‌بندی مختصاتی.
* افکت‌های درخشان نئونی برای متن‌ها، حاشیه‌ها و نشان‌ها متناسب با هر جنسیت.

## 🛠️ راهنمای نصب و راه‌اندازی

برای اجرای پروژه در محیط توسعه محلی، مراحل زیر را طی نمایید:

### ۱. نصب وابستگی‌ها
```bash
npm install
```

### ۲. تنظیم متغیرهای محیطی (اختیاری اما توصیه‌شده)
```bash
cp .env.example .env
```
سپس در فایل `.env` این مقادیر را حتماً تنظیم کنید:
```env
WARROOM_SESSION_SECRET="یک-مقدار-تصادفی-محرمانه"     # تولید: node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
WARROOM_ADMIN_INITIAL_PASSWORD="رمز-نخستین-ورود-مدیر"  # خالی بگذارید تا سرور رمز تصادفی بسازد و یک‌بار در کنسول چاپ کند
WARROOM_COOKIE_SECURE="true"                         # در محیط HTTPS (تولید)
```

### ۳. اجرای هم‌زمان بک‌اند امن و فرانت‌اند (توسعه)
```bash
npm run dev
```
* 🛡️ بک‌اند امن (API): `http://localhost:8787` — همه مسیرهای `/api`
* 🖥️ رابط کاربری (Vite): `http://localhost:3000` (درخواست‌های `/api` به بک‌اند پروکسی می‌شوند)

در صورت نیاز به اجرای جداگانه:
```bash
npm run dev:api     # فقط بک‌اند
npm run dev:web     # فقط فرانت‌اند (با پروکسی /api)
```

### ۴. ساخت و اجرای نسخه نهایی (Production)
```bash
npm run build       # ساخت فرانت‌اند در dist/
npm start           # اجرای سرور امن که هم API و هم رابط کاربری را سرو می‌کند (پورت 8787)
```

> ⚠️ در محیط تولید، سامانه را پشت یک Reverse Proxy با HTTPS (مثلاً Nginx یا Cloudflare) قرار دهید و
> `WARROOM_COOKIE_SECURE=true` و `WARROOM_HSTS=true` را فعال کنید. برای محافظت لبه‌ای (Edge DDoS)
> استفاده از Cloudflare در حالت Proxy توصیه می‌شود؛ لایه محدودسازی نرخ داخلی مکمل آن است.

### ۵. تست و اعتبارسنجی
```bash
npm run lint             # بررسی تایپ‌های TypeScript
npm run security:check   # آزمون خودکار لایه‌های امنیتی (نیازمند اجرای بک‌اند)
npm run supabase:check   # بررسی اتصال Supabase، وجود جدول‌ها و بسته بودن جدول‌های حساس
```

## 🛡️ لایه‌های امنیتی (Security Layers)

سامانه دارای یک **بک‌اند امن (Node.js + Express)** است که همه درخواست‌های حساس را پردازش می‌کند
(`server/`). در صفحه ورود هیچ رمز یا حساب پیش‌فرضی نمایش داده نمی‌شود و رمز عبور کاربران
هرگز به‌صورت متن ساده (Plain Text) ذخیره یا ارسال نمی‌گردد.

| تهدید | راهکار پیاده‌سازی‌شده |
| :--- | :--- |
| **حملات DDoS / DoS** | محدودسازی نرخ Token Bucket + پنجره لغزان (`server/security/rateLimit.js`)، سقف درخواست هم‌زمان هر IP، سقف اتصال سوکت هر IP، سقف حجم بدنه/هدر، زمان‌سنجی ضد Slowloris، مسدودسازی خودکار IP متخلف (۱۵ دقیقه)، حالت تعمیرات و فهرست سیاه/سفید IP |
| **SQL Injection** | هیچ کوئری SQL با رشته‌سازی ساخته نمی‌شود؛ همه دسترسی‌ها از طریق PostgREST (پارامترمحور) یا پایگاه‌داده فایلی انجام می‌شود + اعتبارسنجی و پاک‌سازی کامل ورودی‌ها (`server/security/validate.js`) |
| **رمز متن ساده (Plain Text)** | هش `scrypt` (N=32768) با Salt یکتا برای هر کاربر، مقایسه زمان-ثابت، مهاجرت خودکار رمزهای قدیمی (SHA-256/متن ساده) به scrypt، حذف کامل رمزها از داده‌های سمت مرورگر |
| **Brute-force / جست‌وجوی رمز** | قفل موقت حساب پس از ۶ تلاش ناموفق (۱۵ دقیقه)، تأخیر تصادفی پاسخ، پیام خطای یکنواخت و محدودسازی نرخ سخت‌گیرانه روی مسیرهای ورود |
| **CSRF** | کوکی Double-Submit + هدر `X-CSRF-Token` + بررسی مبدأ (Origin/Referer) روی همه متدهای تغییردهنده |
| **XSS** | Content-Security-Policy، `X-Content-Type-Options: nosniff`، خروجی صرفاً JSON، پاک‌سازی ورودی و رد payloadهای اسکریپتی |
| **Clickjacking / Sniffing** | `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, HSTS (در محیط HTTPS) |
| **دزدی نشست (Session Hijack)** | توکن تصادفی ۲۵۶ بیتی، ذخیره هش‌شده در دیتابیس، کوکی `HttpOnly` + `SameSite=Lax` + `Secure`، انقضای کوتاه مدیر (۴ ساعت) و ابطال نشست‌ها پس از تغییر رمز |
| **افشای اطلاعات در خطاها** | هندلر خطای سراسری بدون Stack Trace، پیام‌های یکنواخت و لاگ ساختاریافته بدون داده حساس |
| **رهگیری و پاسخ‌دهی** | Audit Log کامل (ورود، تلاش ناموفق، درخواست/تغییر رمز، محدودسازی نرخ، عملیات مدیر) + پنل «پایش امنیت» در تب «درخواست تغییر رمز» پنل مدیریت |

### آزمون خودکار امنیت
پس از اجرای بک‌اند، صحت لایه‌های امنیتی را با یک دستور بسنجید:

```bash
npm run security:check
```

نمونه خروجی: محدودسازی نرخ پس از درخواست‌های پیاپی فعال می‌شود، payload تزریقی رد می‌شود،
رمز ضعیف پذیرفته نمی‌شود و پیام خطای ورود اطلاعاتی درباره وجود کاربر فاش نمی‌کند.

## 🔑 ورود مدیر و مدیریت رمز عبور

* **حساب مدیر کل:** کد ملی `0012345678` (تنها یک مدیر کل در سامانه مجاز است).
* **رمز نخستین ورود:** از متغیر محیطی `WARROOM_ADMIN_INITIAL_PASSWORD` تعیین می‌شود. اگر این
  متغیر خالی باشد، سرور یک **رمز تصادفی قوی** می‌سازد و آن را فقط **یک‌بار در کنسول سرور**
  چاپ می‌کند؛ هیچ رمز پیش‌فرض ثابتی در کد یا دیتابیس وجود ندارد و هیچ رمزی
  **هرگز در رابط کاربری نمایش داده نمی‌شود**.
* **تغییر اجباری رمز:** در نخستین ورود، سامانه پنجره «تغییر اجباری رمز عبور» را نمایش می‌دهد و
  تا زمانی که رمز تغییر نکند، تمام عملیات حساس مدیریتی روی سرور مسدود است
  (خطای `PASSWORD_CHANGE_REQUIRED`).
* **بازنشانی رمز کاربران توسط مدیر:** تب «درخواست تغییر رمز کاربران» در پنل مدیریت:
  ۱) مشاهده درخواست‌ها و شماره تماس کاربر، ۲) تماس تلفنی (دکمه تماس/واتس‌اپ/کپی شماره)،
  ۳) تولید یا ورود رمز جدید و ثبت آن روی حساب، ۴) اعلام تلفنی رمز و بستن درخواست.
  رمز جدید فقط **یک‌بار** روی صفحه نمایش داده می‌شود و در دیتابیس تنها هش آن ذخیره می‌گردد.

> 🔐 گزینه‌های مرتبط در `.env`: `WARROOM_ADMIN_INITIAL_PASSWORD`، `WARROOM_ADMIN_FORCE_CHANGE`،
> `WARROOM_LOGIN_MAX_ATTEMPTS`، `WARROOM_LOGIN_LOCK_MINUTES`، `WARROOM_SESSION_SECRET`.

## 🗄️ اتصال به Supabase (دیتابیس ابری)

پروژه به‌صورت کامل برای Supabase آماده شده است. انتخاب لایه ذخیره‌سازی **خودکار** است:

| وضعیت | ذخیره‌ساز | توضیح |
| :--- | :--- | :--- |
| `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY` تنظیم شده باشد | **Supabase** | داده‌های امنیتی و عمومی در ابر ذخیره و بین دستگاه‌ها هم‌سان می‌شوند |
| فقط کلیدهای عمومی تنظیم شده باشند | **پایگاه‌داده فایلی امن** (`server/data`, مجوز 0600) | بک‌اند بدون کلید `service_role` نمی‌تواند در جدول‌های سروری بنویسد |

> ⚠️ کلیدهای `VITE_SUPABASE_PUBLIC_KEY` / `VITE_SUPABASE_ANON_KEY` **فقط برای مرورگر** هستند و
> برای فعال‌شدن ذخیره‌سازی بک‌اند روی Supabase کافی نیستند.

### مراحل اتصال:

**۱) ساخت پروژه:** در [supabase.com](https://supabase.com) یک پروژه جدید بسازید (پلن رایگان کافی است).

**۲) اجرای اسکیمای دیتابیس:** فایل [`Query.sql`](Query.sql) (در ریشه پروژه — نسخه آینه: `supabase/schema.sql`) را در مسیر **SQL Editor → New query** پیست کرده و **Run** کنید. این اسکریپت شامل:
- 🛡️ **۵ جدول امنیتی سرور** (`warroom_credentials`، `warroom_sessions`، `warroom_password_resets`، `warroom_audit_log`، `warroom_security_kv`) با RLS فعال و **بدون هیچ سیاست عمومی**؛ یعنی کلید عمومی (anon) هیچ دسترسی به اعتبارنامه‌ها، نشست‌ها و درخواست‌های تغییر رمز ندارد.
- ۱۸ جدول سند-JSONB منطبق با مدل داده TypeScript (`src/types.ts`) شامل کاربران، جوخه‌ها، مأموریت‌ها، ارسال‌ها، آموزش‌ها، مدال‌ها، تیکت‌ها، اعلان‌ها، اخبار، **ویترین (پست‌ها + نظرات)**، درگاه‌های بازی و تنظیمات
- ایندکس‌های جستجو روی ستون‌های کلیدی (کد ملی، کد اختصاصی، وضعیت تیکت، پست ویترین و...)
- فعال‌سازی **Row Level Security** با سیاست‌های حالت دمو + نسخه سخت‌گیرانه تولیدی (کامنت‌شده در انتهای فایل)
- **داده اولیه: فقط پروفایل «یک» مدیر ارشد** (کد ملی `0012345678`) بدون هیچ رمز عبور + ایندکس یکتای شرطی که افزودن ادمین دوم را مسدود می‌کند؛ اعتبارنامه مدیر توسط بک‌اند امن با هش scrypt ساخته می‌شود
- ساخت باکت Storage عمومی `warroom-media` برای آپلود فایل‌های مأموریت، آواتار و رسانه‌های ویترین

**۳) تنظیم متغیرهای محیطی:** فایل `.env.example` را به `.env` کپی کرده و مقادیر را از مسیر **Project Settings → API** پروژه Supabase وارد کنید:

```env
VITE_SUPABASE_URL="https://YOUR-PROJECT-REF.supabase.co"
VITE_SUPABASE_PUBLIC_KEY="sb_publishable_..."   # کلید عمومی فرمت جدید (اولویت اول — سمت مرورگر)
VITE_SUPABASE_ANON_KEY="YOUR_SUPABASE_ANON_PUBLIC_KEY"  # کلید anon فرمت قدیم (پشتیبان)

# 🛡️ فقط برای بک‌اند (هرگز در مرورگر یا مخزن گیت قرار نگیرد):
SUPABASE_URL="https://YOUR-PROJECT-REF.supabase.co"
SUPABASE_SERVICE_ROLE_KEY="کلید-service-role"
```

> اگر `SUPABASE_SERVICE_ROLE_KEY` تنظیم شود، بک‌اند داده‌های حساس (هش رمز، نشست‌ها، درخواست‌های
> تغییر رمز، رخدادهای امنیتی) را در همان پروژه Supabase ذخیره می‌کند؛ در غیر این صورت از
> پایگاه‌داده فایلی امن روی سرور (`server/data/warroom-db.json` با مجوز 0600) استفاده می‌شود.

**۴) بررسی اتصال (توصیه‌شده):**
```bash
npm run supabase:check
```
این اسکریپت دسترسی به پروژه، وجود ۱۸ جدول عمومی، **بسته بودن ۵ جدول حساس** در برابر کلید
عمومی و آماده بودن کلید `service_role` را گزارش می‌کند.

**۵) اجرا:** برنامه را ری‌استارت کنید. اکنون کل اپلیکیشن به Supabase متصل است:
- ثبت‌نام و ورود کاربران روی جدول `warroom_users` (با هش SHA-256 رمز) انجام می‌شود
- **تمام مجموعه‌های داده** (کاربران، جوخه‌ها، مأموریت‌ها، ارسال‌ها، آموزش‌ها، مدال‌ها، تیکت‌ها، پاسخ‌ها، اعلان‌ها، اخبار، نوتیفیکیشن‌ها، اطلاعیه‌ها، FAQ، **ویترین و نظرات**، درگاه‌ها و تنظیمات) به‌صورت خودکار در Supabase همگام می‌شوند
- ویترین‌های جدید از تب «ویترین آثار» پنل مدیریت (با آپلود مستقیم رسانه به Storage) یا از بخش داوری/تأیید آثار منتشر می‌شوند
- تنظیمات CMS، لیست موسیقی و ذخیره‌های کاربران در جدول `warroom_kv` ذخیره می‌شوند

### معماری لایه داده:
```
src/lib/supabaseClient.ts   → ساخت کلاینت Supabase از env (Lazy + تشخیص خودکار حالت + Health Check
                              + آپلود فایل به Storage + پشتیبانی کلیدهای فرمت جدید/قدیم)
src/lib/supabaseData.ts     → هوک‌های useSyncedCollection / useSyncedSetting
                              (بارگذاری اولیه از دیتابیس + Diff-Sync خودکار + fallback به localStorage)
                              + همگام‌سازی Bookmark کاربران با ابر
server/                     → 🛡️ بک‌اند امن: سرور API، محدودسازی نرخ (ضد DDoS)، هش scrypt،
                              اعتبارسنجی ورودی (ضد SQLi/XSS)، نشست امن، CSRF، Audit Log
Query.sql                   → Query کامل ساخت دیتابیس: ۱۸ جدول عمومی + ۵ جدول امنیتی، ایندکس‌ها، RLS، Storage
```

> **نکته امنیتی برای انتشار عمومی:** سیاست‌های جدول‌های عمومی برای توسعه/دمو باز هستند (جدول‌های حساس کاملاً بسته‌اند).
> پیش از عرضه عمومی، بخش «سیاست‌های سخت‌گیرانه تولیدی» در انتهای `Query.sql` را اعمال کنید و
> مسیرهای خواندن/نوشتن عمومی را به API بک‌اند (که نشست و نقش کاربر را اعتبارسنجی می‌کند) منتقل نمایید.

## 📝 گزارش اقدامات و کارهای انجام‌شده (Changelog)

### 🛡️ نسخه ۲.۲ — لایه‌های امنیتی، بک‌اند واقعی و بازیابی امن رمز عبور

1. **ساخت بک‌اند امن (رفع مشکل «کار نکردن بک‌اند»):**
   - افزودن سرور Node.js/Express در پوشه `server/` با مسیرهای `/api` (سلامت، احراز هویت، درخواست تغییر رمز، مدیریت).
   - راه‌اندازی هم‌زمان بک‌اند و فرانت‌اند با `npm run dev` (پروکسی `/api` در Vite) و سرو نسخه تولید با `npm start`.
   - لایه ذخیره‌سازی دوگانه: Supabase (با کلید `service_role` روی سرور) یا پایگاه‌داده فایلی امن — دیگر برنامه برای داشتن دیتابیس مشترک به تنظیم دستی Supabase نیاز ندارد.
2. **لایه‌های ضدحمله:**
   - **ضد DDoS/DoS:** محدودسازی نرخ Token Bucket + پنجره لغزان، سقف درخواست/اتصال هم‌زمان هر IP، مسدودسازی خودکار IP متخلف، کندسازی تدریجی، سقف حجم بدنه و محافظت Slowloris.
   - **ضد SQL Injection:** حذف کامل رشته‌سازی SQL (PostgREST پارامترمحور) + اعتبارسنجی/پاک‌سازی همه ورودی‌ها.
   - **ضد رمز متن ساده:** هش `scrypt` با Salt یکتا، مقایسه زمان-ثابت، مهاجرت خودکار رمزهای قدیمی و حذف رمز از داده‌های مرورگر.
   - **ضد Brute-force:** قفل موقت حساب، تأخیر تصادفی، پیام یکنواخت خطا (بدون افشای وجود کاربر).
   - **CSRF/CSP/XSS:** توکن دوگانه CSRF، بررسی مبدأ، سرصفحه‌های امنیتی، خروجی JSON و اعتبارسنجی ورودی.
   - **Audit Log و پایش امنیت:** ثبت رخدادها + بخش «پایش امنیت» (آمار حملات، IPهای مسدود، رخدادها) در پنل مدیریت.
   - ابزار آزمون خودکار: `npm run security:check`.
3. **حذف رمز پیش‌فرض از رابط کاربری:**
   - حذف کامل باکس «حساب پیش‌فرض مدیر» از صفحه ورود؛ هیچ رمزی در UI نمایش داده نمی‌شود.
   - حذف رمز متن ساده از کد (`src/data.ts`) و از اسکریپت دیتابیس (`Query.sql`).
   - تغییر اجباری رمز در نخستین ورود مدیر (`must_change_password`) و مسدودسازی عملیات حساس تا زمان تغییر رمز.
4. **جریان امن «فراموشی رمز عبور»:**
   - کاربر با کد ملی + شماره تماس، درخواست با کد رهگیری ثبت می‌کند (امکان تغییر مستقیم رمز حذف شد).
   - تب جدید «درخواست تغییر رمز کاربران» در پنل مدیریت: مشاهده درخواست‌ها، نمایش شماره تماس (تماس مستقیم/واتس‌اپ/کپی)، ثبت تماس تلفنی، تولید یا ورود رمز جدید، ثبت روی حساب کاربر، اعلام تلفنی و بستن/رد درخواست.
   - رمز جدید فقط یک‌بار نمایش داده می‌شود؛ در دیتابیس تنها هش scrypt ذخیره می‌گردد.
5. **امنیت پنل مدیریت کاربران:**
   - حذف نمایش رمز کاربران در جزئیات کاربر و حذف رمز پیش‌فرض `123` در فرم ایجاد کاربر.
   - ایجاد/ویرایش کاربر از مسیر امن سرور با رمز یک‌بارمصرف و هش‌شده؛ افزودن فیلد شماره همراه به فرم ثبت‌نام برای هماهنگی تلفنی.

1. **آماده‌سازی کامل پروژه برای دیتابیس Supabase:**
   - افزودن کتابخانه `@supabase/supabase-js` و ساخت کلاینت Lazy از متغیرهای محیطی.
